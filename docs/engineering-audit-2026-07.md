## 2. Scope boundary with issue #46

Issues #46 and #55 partition the repository, and neither judges the other's surface (requirement 1).

- **#46 owns the agent-facing prompt surface**, judged as context engineering:
  `skills/code-gauntlet/SKILL.md`, `skills/code-gauntlet/references/`, `skills/build-review-md/`,
  and the bodies of `agents/*.md` read as prompts. The `/doctor` rightsizing pass belongs there.
- **This audit owns first-party executable code and engineering practice**, judged as software
  engineering: `scripts/`, `workflows/src/`, `workflows/test/`, `tests/`, `bench/`, plus the
  toolchain, CI, and repository configuration around them.
- **The overlap is `CLAUDE.md` and the `AGENTS.md` family only.** They are audited here strictly as
  rules files, for factual accuracy against the code they describe (section 13). Their length,
  ordering, and prompt-economy — rightsizing — are deferred to #46 and are not judged here.

## 3. Method

Three stages, then an adversarial pass over the one axis where the output is a set of claims about
the codebase rather than a tool number.

1. **Evidence.** Seven agents ran real tools — coverage.py, ruff, mypy, Biome, oxlint, `tsc`,
   jscpd, zizmor, `gh api` — with every venv, cache, config, and report confined to a scratchpad
   outside the tree (test runs execute from the repository root by necessity; nothing was written
   into it, and `git status --porcelain` was confirmed clean afterwards).
2. **Research.** Four agents established mid-2026 practice with citations, per axis. Research
   proposals were treated as input to judgment, not as conclusions — several were rejected on this
   repository's numbers.
3. **Judgment.** Five opus agents audited comment/docstring and rules-file accuracy, producing the
   60 allegations of section 12.
4. **Blind challenge and synthesis.** Every allegation was re-verified by an independent agent that
   saw the quoted comment and the file but not the auditor's reasoning; disagreements were
   adjudicated by a third opus agent. Of 60 allegations, 58 were confirmed, 1 revised, 1 rejected.
   The same pass classified every duplication and produced six opus decision memos, one per axis,
   each recording options considered with verdicts, quick wins, owner decision points, and a
   follow-up issue specification. Seventy-one agents ran across this pass.

need a hand-maintained exception list — the "add more text" smell), a single blended threshold, a
pre-commit gate (CI's lint job installs only `pre-commit`), a new CI job, and any third-party
coverage service. Follow-up: **#102**.

## 6. JavaScript coverage

**Measured.** `node --test --experimental-test-coverage workflows/test/*.test.js` on Node
v24.18.0: 596/596 pass, aggregate **98.98% line / 83.16% branch / 98.37% function** across
`workflows/build.js` and eight `workflows/src/*.js` modules. Lowest branch coverage: `stages.js`
78.51%, `applyValidations.js` 82.61%, `filterFindings.js` 84.19% — read individually, and uniformly
defensive guards, degrade-and-record-gap paths, or Python-`int()` parity fallthroughs, with one
exception (`filterFindings.js:709-711`, the `type_design` arm of the dimension classifier, which is
real untested logic).

Node v24.18.0 supports the threshold flags natively (`--test-coverage-lines`, `-branches`,
`-functions`, plus `--test-coverage-include` / `--test-coverage-exclude`), so no third-party tool is
needed. Two measured facts shape the recommendation:

- Aggregate branch coverage is **not** deterministic run to run: over 30 runs of the identical
  command on the identical tree, 25 reported 83.16 and 5 reported 83.00. Line and function were
  stable across all 30. A baseline-tight branch threshold would flake roughly one run in six.
- Supplying **any** `--test-coverage-exclude` overrides Node's built-in exclusion of test files and
  silently pulls all 16 test files and both helpers into the report, moving the aggregate to
  99.43 / 87.76 / 97.45. The gate would then be measuring the tests.

`workflows/pipeline.js` is absent from the report today only by accident — no test imports it
(`grep -rn "pipeline.js" workflows/test/` returns nothing; `build.test.js` builds the bundle in
memory and never reads the file).

**Disposition.** Amend the single existing `Run node test suite` step in the `workflow-tests` job to
run with coverage and floors of 98 line / 82 branch / 97 function, and make the bundle exclusion
deliberate with an **include allowlist** (`--test-coverage-include='workflows/src/*.js'` and
`'workflows/build.js'`) rather than an exclude flag. Pin `node-version` from `"24"` to `"24.18.0"`.
Verified exit 0 as written at `ebf399d`; raising the branch flag to 90 produces exit 1, so the gate
is live. Test files and helpers are not gated — `pipelineMock.js` is a fixture, and gating it would
let mock affordances move the product number. Rejected: c8/nyc (needs `package.json` and
`node_modules`), per-file thresholds (Node's flags are global-only), a second job, and a coverage
service. Follow-up: **#103**.

## 8. JavaScript lint, format, and type

**Measured** over `workflows/src/*.js`, `workflows/build.js`, and `workflows/test/*.js` from an
isolated scratchpad, with the repository used only as an absolute-path target:

| Tool | Result |
| --- | --- |
| Biome 2.5.6 | 180 diagnostics (66 errors, 113 warnings): noUnusedFunctionParameters 55, useOptionalChain 51, format 32, organizeImports 24, noAssignInExpressions 7, noUnusedVariables 5, others 6 |
| oxlint 1.76.0 | 23 diagnostics: no-unused-vars 11, prefer-string-starts-ends-with 7, no-useless-fallback-in-spread 3, others 2 |
| `tsc` 7.0.2 `--checkJs` | 453 errors, of which TS7006 (implicit any) 343 — 76% |

Two diagnostic classes are false positives against documented design: the workflow-host-injected
globals `agent`/`parallel`/`pipeline`/`args`, and `pipeline_entry.js`'s top-level `return`, which is
its entry contract. Separately, `workflows/src/*.js` contains **zero** JSDoc `@param`/`@returns`/
`@type`/`@typedef` tags, which is why `--checkJs` produces almost no real signal.

Requirement 3a asks for the no-npm trade laid out as options with mechanisms:

- **(i) Keep the constraint, ship no JS tooling.** Mechanism: nothing. Cost: 5,638 source + 111
  build + 7,787 test lines with no static analysis, and — decisively — the sandbox-absent-globals
  invariant is enforced only dynamically, by `pipeline_run.test.js` deleting six globals from
  `globalThis`. `workflows/AGENTS.md` records that a stray reference "throws on the first live
  dispatch while every test stays green".
- **(ii) CI-only tooling, zero repo-tree npm footprint.** Mechanism: a pinned, checksum-verified
  Biome static binary downloaded into `$RUNNER_TEMP` in a new `js-lint` job; one new tracked file,
  `workflows/biome.json`; no `package.json`, no lockfile, no `node_modules`; the shipped pipeline
  keeps zero dependencies. This sits inside a line already drawn — `validate.yml` runs
  `npm install -g @anthropic-ai/claude-code` on every PR today, so npm already executes on the
  runner; the constraint as practised governs the tree and the shipped runtime.
- **(iii) Relax the no-npm rule.** Mechanism: `package.json` at root plus ESLint/Prettier. Cost: a
  lockfile, an npm-audit and dependabot surface, and a contributor-facing `npm install`. ESLint is
  the only researched tool that requires it, and it covers no signal Biome misses.

**Disposition.** The recommended default is **option (ii) in its narrowest form: Biome 2.5.6,
lint-only, formatter off, no type checking**, with `linter.rules.recommended: false` and an explicit
ON list — the highest-value rule being `noRestrictedGlobals` denying the sandbox-absent globals, so
the invariant gains a static guard. Rules left off carry their hit count as the reason
(useOptionalChain 51, noUnusedFunctionParameters 55, noAssignInExpressions 7, organizeImports 24).
Formatting is deferred behind a real prerequisite, not taste: Biome's default `lineWidth: 80` would
wrap `stages.js:18` (163 chars), and `build.js`'s import-stripping regex requires `from` on the same
line, so a wrapped import would survive into the bundle and fail
`tests/test_bundle_fresh.py`. Rejected: oxlint as primary (23 diagnostics, 11 of them pure style,
for a second pinned binary), `tsc`/`tsgo` and `deno check` (the blocker is missing JSDoc, not a
missing runner), ESLint without `package.json` (upstream says it is effectively required), and
quick-lint-js (pre-release).

**Which option to take is the owner's decision, not this audit's.** Option (ii) requires accepting
`workflows/biome.json` as a tracked JS-ecosystem file and restating the no-npm rule in `AGENTS.md`
to say what it actually governs. Both are constraint changes, and constraint changes are owner-only.
Follow-up: **#105**.

## 9. Security tooling

**Already correct — no action, and not to be re-litigated.** CodeQL *default setup* is configured
with all five languages (`actions`, `javascript`, `javascript-typescript`, `python`, `typescript`),
`query_suite: default`, `threat_model: remote`, weekly plus push and PR. There is no Python or
JavaScript coverage gap; `actions` is an additional language that analyses workflow YAML, not a
substitute. Secret scanning, push protection, non-provider patterns, and validity checks are all
enabled, with gitleaks in pre-commit as the local layer. `SECURITY.md`, `.github/CODEOWNERS`, and an
octo-sts trust policy scoped to `contents: write` on `refs/heads/main` all exist.

**SonarQube Cloud: evaluated and declined.** It is free and unlimited for public repositories, so
the cost is not money. Declined because 58% of the lines it would analyse are tests, CodeQL already
covers both first-party languages on push, PR, and weekly, and with no `pyproject.toml`, no
`package.json`, and no published coverage report its default quality gate fails on day one. The
residual cost is a GitHub App install on the org plus a false-positive triage queue for one person.

**The supply-chain gap is real.** zizmor 1.28.0 over `.github/workflows` reports 31 findings:

- **23 High `unpinned-uses`** — 23 of the 24 `uses:` references across 7 files and 10 distinct
  actions are pinned by mutable tag, not commit SHA. The single exception is the SHA-pinned
  reusable-workflow call in `publish-marketplace.yml`. `actions/checkout` is also split across two
  majors (v4 and v6).
- **6 Medium + 1 Low `artipacked`** — all 7 `actions/checkout` steps except `release.yml`'s omit
  `persist-credentials: false`, so the ephemeral token is written to `.git/config` and lingers for
  the rest of the job.
- **1 Low `adhoc-packages`** — an unpinned global npm install.
- **No `.github/dependabot.yml` at all**, and `dependabot_security_updates` measured as `disabled`.
  Nothing moves a pin forward.
- **Three workflows declare no `permissions:` block** (`bench-smoke.yml`, `ci.yml`,
  `pr-title-lint.yml`) and inherit the repository default.

No `pull_request_target` or `workflow_run` triggers exist anywhere, and no script-injection sink was
found. The exposure is the tj-actions class (CVE-2025-30066, ~23k repositories, CISA alert): a
repointed tag on `octo-sts/action@v1.1.1` executes attacker code in the job that mints a
`contents: write` federated token.

**Disposition.** One PR: SHA-pin all 23 `uses:` with `# vX.Y.Z` trailing comments resolved via
`gh api`, add `persist-credentials: false` to all 7 checkouts, add top-level `permissions:` to the
three workflows lacking one, add `.github/dependabot.yml` (github-actions ecosystem, weekly,
grouped into one PR, `commit-message.prefix: chore` — load-bearing, because Dependabot's default
subject fails `pr-title-lint.yml`), pin every in-workflow package install, and gate the whole thing
with **zizmor in pre-commit** plus a committed `.github/zizmor.yml` setting
`unpinned-uses: {"*": hash-pin}` so a future tag pin fails rather than warns. Pinning and Dependabot
ship together — pinning alone converts a mutable-tag risk into a stale-commit risk. Rejected:
SonarQube Cloud, pip-audit/osv-scanner (no manifests, stdlib-only runtime), dependency-review (would
pass vacuously), harden-runner, Allstar, the OpenSSF Best Practices badge, and CodeQL
`security-extended` (triage capacity is the binding constraint, not query recall). Follow-ups:
**#106**, and **#107** for the OpenSSF Scorecard action and badge, filed
separately and sequenced *after* pinning so the first published score reflects the fixed state.

## 10. Repository protections

**Measured** via `gh api` on 2026-07-30.

- Exactly one ruleset exists: `protect-default-branch`, id **16049246**, enforcement `active`,
  condition `~DEFAULT_BRANCH`, carrying three rules — `deletion`, `non_fast_forward`, and
  `pull_request` with `required_approving_review_count: 0`. **There is no required-status-checks
  rule**, so nothing CI reports can block a merge: a PR with `Run Tests (3.12)` red is mergeable
  today with one click. This is the headline finding of the axis.
- **No tag ruleset exists.** `.releaserc.toml` sets `tag_format = "v{version}"` and CI pushes those
  tags (most recent `v3.3.4`), so every released tag is currently movable and deletable.
- The ruleset grants Integration actor 801323 (`gh api /apps/octo-sts` confirms it is the Octo STS
  app) `bypass_mode: always`. That is not a human escape hatch — the token can only be minted by a
  workflow presenting the pinned OIDC subject — but the trust policy in
  `.github/chainguard/main-semantic-release.sts.yaml` carries no workflow-path constraint, so any
  workflow on `main` can request it.
- `delete_branch_on_merge` is false, and merge commits and rebase merging are both still allowed
  alongside squash.
- **Private Vulnerability Reporting is already enabled** (`{"enabled": true}`) and already
  documented in `SECURITY.md`. Closed; strike it from any remaining hardening list.
- **The AGENTS.md/CLAUDE.md twin drift check already exists and passes** (section 13), so none needs
  building. It is unenforced for the same reason as the first bullet: `Run Linting` is not required.

**Disposition.** Add a required-status-checks rule to ruleset 16049246 naming exactly the nine
contexts that report on every PR (`Run Linting`, `Run Tests (3.10|3.11|3.12)`,
`Run Workflow JS Tests`, `Run Bench Self-Tests (3.11|3.12)`, `Validate plugin.json`,
`lint-pr-title`), leaving "require branches up to date" off. Do **not** require CodeQL/Analyze,
Cursor Bugbot, or labels-verify — each can decline to report, leaving a PR permanently pending.
Keep `required_approving_review_count: 0`: GitHub blocks self-approval, so any nonzero value
deadlocks a single-owner repository. Add a tag ruleset on `refs/tags/v*` with Restrict deletions and
Restrict updates only — deliberately not Restrict creations, so a stale bypass entry cannot break a
release. Freeze the check-run names in `tests/test_contribution_surface.py`, derived from the
workflows' `name:` and `python-version:` lines, so a job rename cannot silently un-gate the ruleset;
that file is also the right home for making the twin-sync drift check enforcing. Scope the octo-sts
trust policy to `release.yml` via a `job_workflow_ref` claim pattern. Prefer squash-only merges over
a `required_linear_history` rule: it yields linearity as a side effect *and* fixes a correctness gap,
since `squash_merge_commit_title` is `COMMIT_OR_PR_TITLE`, so squash-only is what makes the title

## 11. Duplication

## 12. Comment and docstring accuracy

**Method.** Four evidence agents read `scripts/`, `workflows/`, `tests/`, and `bench/` and alleged 60
comment-rot findings — cases where a comment, docstring, banner, or cross-reference states something
the code does not do. Every allegation was then re-verified by an independent agent that saw the
quoted text and the file but not the auditor's reasoning, with disagreements adjudicated by a third
