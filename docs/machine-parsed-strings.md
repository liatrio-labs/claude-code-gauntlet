# Machine-parsed strings

Living registry of exact strings another component parses. **Add a row before
introducing a new machine-parsed token.** CI
(`tests/test_machine_parsed_strings.py`) asserts each `string` appears in
**every** listed producer **and every** listed parser (presence/bytes only).

Every listed path must contain the exact bytes. A path that does not is a
phantom: it makes the row look cross-checked while the only file actually
proving the string is the producer itself. When no component parses the bytes —
the reader matches them by regex, or the string is a two-copy invariant with no
machine reader at all — write `—` in the parser column and say why in the notes.
That is an honest empty, and the test enforces the explanation.

Tracking: issue #37. Sibling point-in-time audit:
[v3-residue-audit-2026-07.md](v3-residue-audit-2026-07.md).
